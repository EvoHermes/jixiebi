# A130 视觉控制

先定位用户当前使用的固件和树莓派版本，读取项目的 PROJECT_MEMORY.md 与工作区规则，并检查 Git 状态。保留已有未提交改动；历史 outputs/ 示例不能代替当前运行代码。旧源文件存在混合编码，修改时保留未改区域的字节，避免整文件转码。

本机项目线索、已确认协议和验证方法见 [references/project-context.md](references/project-context.md)。其中参数是 2026-10-30 的版本快照，遇到新版本时以实际发送端、接收端及用户最新要求为准，不把旧参数强行写回。

## 按问题定位

- 协议对齐：检查 Pi 实际编码器、摄像头分辨率、裁剪/缩放及坐标转换，再核对 STM32 接收解析器。明确原点、轴方向、边界是否包含、端序、校验和、发送周期、无目标处理及完成回包。数据帧表达目标位置，速度在控制器配置中调整。
- 方向和 PID：追踪从像素误差到关节命令再到 PWM 的完整符号链。J1 的 PWM 转换还有一次符号处理，不能只凭增益正负推断物理转向。先核对用户实测方向，再调整一个轴。区分视觉外环与 PWM 命令平滑内环；按新坐标更新，保留限速、关节限位、积分抗饱和、失效复位和微分滤波。参数必须标注单位与采样时间，不能把起始值称为实机最优值。
- 抓取时序：保持未居中不抓取；满足居中条件后先开 J6，再移动 J1-J5，前伸输出稳定后闭合，闭合输出稳定后收回。保持目标丢失、偏离、逆解失败和阶段超时的退出路径。检查回程完成回包与下一轮重新使能，避免旧坐标流连续触发。
- 用户要串口测试数据：提供坐标、完整十六进制帧和校验和，说明重复发送的行为。连续中心帧可能启动实际抓取，不能当作纯云台方向测试。

## 验证与交付

修改状态机或解析器后，先从当前源码重新生成主机测试快照，再运行回归；涉及 Pi 协议时使用对应版本的真实编码器对照测试。随后编译实际 Keil 工程并检查日志和 HEX，不以进程退出码单独断言编译成功。具体入口见参考文件。

主机测试里的硬件、中断及逆解使用桩函数，不证明物理运动、真实逆解或抓取成功。PositionN 是输出 PWM 命令而非独立测量的舵机位置；输出稳定不能称为机械轴已实测到位。编译成功也不等于已经烧录。

完成后用中文说明修改行为、验证结果、固件路径与未验证事项；同步项目记忆中的协议、参数和验证状态。保存到 GitHub 时先明确本次文件范围，排除 Keil 许可证信息、个人 IDE 状态及不需要的生成文件；不要把整个脏工作区自动打包提交。
